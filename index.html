Critical Thinking Lab

01 — Cascade investigation

Before I removed the rule

I first opened the page in my browser and used Developer Tools to inspect one review box. I could see that the review had the tan background specified by the .review selector.

The change I made

I temporarily removed the background declaration from the .review rule in styles.css. 

.review {
    display: flex;
    align-items: flex-start;
    margin: 0 0 10px;
    padding: 8px;
    border: 2px solid #777777;
    background: #e1d697;
    color: #111111;
    font-weight: bold;
}

After I removed it

After I removed the declaration and refreshed the page, the review no longer had the tan #e1d697 background. I could see the background of the surrounding section instead.

Why the browser paints it that way

I first checked the .review selector. It is a class selector, so it has class-selector specificity and applies to every review element with that class. I then checked the matching declarations and their source order. The original .review rule supplies the tan background. When I removed that declaration, there was no later matching rule giving the review its tan background, so the surrounding background became visible. I restored the rule after taking my evidence screenshots. 

.review {
    background: #e1d697;
}

02 — Responsive trade-off

My 480px test

I first set the browser viewport to exactly 480px wide. I selected the main review region and the General Overview sidebar in Developer Tools and recorded their computed widths.

Main review region (#review-main): 468 px

Sidebar / overview (#overview): 468 px

Viewport width: 480px

The trade-off I made

I first kept the desktop two-column layout, but the 800px frame would be too wide for a 480px viewport. I therefore made the major regions stack vertically at the responsive breakpoint. I gave up the side-by-side desktop appearance so the page would fit without horizontal scrolling.

The layout value I changed

I changed the small-screen frame from the desktop fixed-width behavior to a viewport-relative value: 

#movie-page,
#stats {
    width: calc(100% - 8px);
    max-width: none;
}

The review columns also become one column at the small breakpoint, which gives the review text more usable width.

Why my final value is better

I chose the final value because it keeps the main frame inside the viewport while leaving a small amount of space around it. The page still keeps the important hierarchy: movie title, overview, reviews, and review counter.

03 — Architecture defense

Why I used Grid

I used CSS Grid for the relationship between the main review area and the General Overview because these are major page regions that need a two-dimensional layout. I named the areas reviews and overview, then changed their arrangement at the responsive breakpoint. 

#movie-page {
    display: grid;
    grid-template-columns: minmax(0, 550px) 250px;
    grid-template-areas: "reviews overview";
}

Why I used Flexbox

I used Flexbox inside each review because the icon and review text form a one-dimensional relationship. The icon stays on the left and the review body uses the remaining space. I also used Flexbox for reviewer metadata so the critic icon can wrap when the screen becomes smaller. 

.review {
    display: flex;
    align-items: flex-start;
}

.critic-info {
    display: flex;
    align-items: center;
    flex-wrap: wrap;
}

My measurements

700px main region width: 676 px

700px overview width: 676 px

700px horizontal overflow: 0 px

480px main region width: 468 px

480px overview width: 468 px

480px horizontal overflow: 0 px

I chose Grid for the major frame because it controls rows and columns and lets me rearrange the page at a breakpoint without changing the HTML order. I chose Flexbox for the review metadata because it is a repeated, one-dimensional component.

04 — Failure analysis

The defect I introduced

I made a separate copy of the page so the original evidence would remain unchanged. In the defect copy, I temporarily changed the 480px frame width to 800px. 

@media (max-width: 480px) {
    #movie-page,
    #stats {
        width: 800px;
        max-width: none;
    }
}

What happened

I refreshed the defective copy at 480px. The main frame became wider than the viewport, so the browser produced horizontal scrolling.

What Developer Tools showed

Defective computed width: 800 px

Viewport width: 480px

Horizontal overflow: Yes

My diagnosis and correction

I first reproduced the problem and then selected #movie-page in Developer Tools. The Computed panel showed that the frame was wider than the viewport. I traced the problem to the fixed width on the parent frame. I changed the width back to a viewport-relative value: 

#movie-page,
#stats {
    width: calc(100% - 8px);
    max-width: none;
}

I refreshed the page and checked the same element again. The corrected frame fit inside the viewport without replacing the original evidence.

Corrected computed width: 472 px

Horizontal overflow: No
